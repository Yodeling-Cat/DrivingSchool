# Importing the question banks

The app bundles its questions and images as Compose resources. They are generated by the importer in `tools/import/`. Don't edit the generated files by hand; re-run the importer. For what the sources are, see [data-sources.md](data-sources.md).

## Run it

You need Python 3.10 or newer on your `PATH`. The script creates a virtualenv in `tools/import/.venv` on first run and installs `requirements.txt` into it.

```bash
./tools/import/import.sh
```

On Windows PowerShell:

```powershell
.\tools\import\import.ps1
```

Options:
- `--refresh`: download the sources and images again, even if they are cached. Use this when updating to new data from minv.sk.
- `--version N`: the bank version to write. It defaults to 1. See "Updating to new data" below.
- `--help`: show usage.

Downloads are cached in `tools/import/cache/`, which is gitignored. Without `--refresh`, the importer only processes the cached files.

## What it writes

The output goes to `app/shared/src/commonMain/composeResources/files/`, and it is committed:

| Path | Contents |
|---|---|
| `banks/index.json` | The latest version of every bank, with its question count per license group. The exam-selection screen reads this. |
| `banks/<bank>-v<version>.json` | One version of one bank, such as `sk-sk-v1.json`: its topics (`sections`) and questions. It is decoded by `QuestionBank` in `:core`. |
| `images/minv-sk/...` | The images the questions reference, with the same paths as on minv.sk. Images that no bundled bank version references are deleted. |

The app loads these files with `QuestionBankRepository`, in `app/shared/.../data/`.

## How it works

1. **Download** `data5.js` and the Slovak and Hungarian PDFs (URLs at the top of `import_minv.py`).
2. **Parse `data5.js`.** For each language, collect every question with its topic, points, the three answers, the correct answer and the image.
3. **Parse the PDFs.** `minv_pdf.py` uses PyMuPDF's table detection. The group cell is normalised: `B`,`E` becomes `BE`, and page numbers that leak into the cell are dropped. An empty cell means all groups.
4. **Match the two.** Match on topic plus normalised question and correct-answer text. If there is no exact match, use a fuzzy match (≥ 0.85 similarity). Duplicate rows are assigned in order.
5. **Write** the banks and the index, and download the images they reference.

The importer prints how many questions it matched and dropped. Compare those numbers with the table in `data-sources.md`, and update the table when they change.

## Updating to new data

There are two kinds of update:
- **Fixes to the current question set** (typos, reformatting, parser fixes): re-import the **same** version. Question ids stay the same, so recorded attempts still match.
- **A new official question set** (the ministry publishes new or changed questions): import it as a **new version**, e.g. `--version 2`. Keep the old `-v1.json` files; the importer leaves them, and their images, in place. The app starts new tests on the new version, and old attempts keep pointing at v1. See "Question bank versions" in `AGENTS.md`.

Steps:

1. Run `./tools/import/import.sh --refresh`, adding `--version N` for a new question set.
2. Check the output for unmatched questions or big changes in the counts.
   Then run `./tools/import/test.sh`. `test_bank_output.py` fails if a question is malformed, an image is missing, or a group can no longer fill a full exam.
3. If the PDF links changed (they are `subor=<id>` links on <https://www.minv.sk/?elektronicke-testy>), update `PDF_URLS` in `import_minv.py`.
4. Build and try the app. Test numbers are generated from the bank, so changing a bank's questions reshuffles its practice tests. This is another reason to put a new question set in a new version.
5. Update "Last imported" and the counts in `data-sources.md`, then commit the regenerated resources.

## Adding a new source

For example, the Czech tests:
1. Write a new `import_<source>.py` next to `import_minv.py`.
2. It must write versioned banks in the same JSON format (see `QuestionBank.kt`), add its entries to `banks/index.json` without removing other countries' entries, and put its images in its own `images/<source>/` directory, referenced by the bank's `imageDir`.
3. Add the country name in `onboarding/ExamLabels.kt`, plus labels for any new language.
4. Document the source in `data-sources.md`.
