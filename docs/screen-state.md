# Screen state

Where each screen was — how far it was scrolled, which page of a pager, the tab that was open — is kept by `ProvideStoredScreenState` (`screenstate/`), which `App()` wraps the whole app in. It provides a `SaveableStateRegistry` that writes to `Settings` in place of the platform's own registry, so `rememberSaveable`, `rememberScrollState` and `rememberPagerState` come back where they were on **every** platform, not only where the platform restores state itself (Android's saved instance state, a browser's address bar). A killed app then opens on the screen it was left on *and* at the place in it: the question a test was on, rather than the first unanswered one.

- **A screen needs nothing.** Use `rememberSaveable` and the state helpers as usual; the registry is above every screen and above onboarding.
- **Written as the app leaves the front** (`LifecycleEventEffect(Lifecycle.Event.ON_STOP)`, which is also the moment before a phone's system kills it) and every 500 ms while it is in use, and only when what would be written has changed — compared as *text*, because Compose's savers hand over a freshly built object every time they are asked (Navigation 3's screens do). Only asking the screens for their state (`performSave`) runs on the main thread. Turning it into text, comparing it and writing it run on a single-threaded writer off the main thread, one save at a time and in order.
- **Only values `ScreenStateText` understands are stored** — numbers, strings, booleans, characters, lists, maps and the `Pair` keys Navigation 3 tells its screens apart by, which is what Compose's savers make. A value it cannot write is **left out** of the state rather than failing the write (Navigation 3's map of screens carries the platform's own saved state for each screen inside it), and it is registered with the platform registry as well, so nothing the platform keeps is lost. What the platform holds is preferred when a screen asks for its state back: it is written later than this.
- **Bump `ScreenStateText.VERSION` when the shape of the text changes.** A state that cannot be read reads as *no* state, so a screen loses its position rather than being handed a value it can't use.
