# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository. `CLAUDE.md` imports it.

It holds what every change needs. Each area has its own guide in `docs/`: **read the guide before you work in its area** — "Topic guides" below says which one applies when.

## Project overview

NajAutoskola is a Kotlin Multiplatform driving-theory app (tests + learning resources for new drivers). It targets Android, iOS, Web (JS + Wasm via Compose Multiplatform), and ships a Ktor JVM server.

Root package is `com.spiraclestudios.autoskola` across every module. The released app's `applicationId` and Gradle `group` are also `com.spiraclestudios.autoskola`; a debug build appends `.dev`, so it installs alongside a released app and keeps its own data. A build targeting Czechia appends `.cz`. Gradle root project name is `NajAutoskola`.

## Language and spelling

Write **American English** everywhere in this repository — code, identifiers, comments, KDoc, docs, plans, commit messages, and the English strings in `i18n/Strings.kt`.

The other three tables in `i18n/Strings.kt` are Slovak, Hungarian and Czech, and the question content is the bank's own language — neither is English and neither is affected.

Two things the rule does **not** reach, because they are not our text:

- The generated question banks in `app/content/<country>/src/commonMain/composeResources/files/`. Their wording is the ministry's published translation and must never be hand-edited (see [docs/question-banks.md](docs/question-banks.md)). Respelling it would change exam content and stop the app matching the official text.
- `aboutlibraries.json`, whose `organisationUrl` is a field name from the AboutLibraries schema, regenerated by `./gradlew :app:shared:exportLibraryDefinitions`.

## Tests first

Tests are the primary consumer of our code; the human user comes second. Every change follows these rules:

1. **Write the test first.** Prefer strict TDD: write one failing test, make it pass with the simplest code, refactor, then write the next test. Run the test and see it fail before you write the implementation.
2. **Design for testability.** Keep decisions and rules in plain Kotlin that a unit test can call:
   - Scoring, what to resume, which questions count as mistakes and which answers are locked all belong in `:core`, in `ExamSession` or in ViewModels, never inline in a composable.
   - Composables should only render state and forward events.
   - Inject what a test needs to control: `Settings` (use `MapSettings` in tests), data sources (fakes like `FakeQuestionBankDataSource`), clocks (`now: () -> Long`) and randomness (`Random`).
3. **Test what matters most, not everything.** Aim at domain logic, persistence, data import and state decisions, where bugs would silently corrupt a user's progress or give wrong answers. Don't chase coverage numbers, and don't test Compose layout details.
4. **Keep tests fast and deterministic.** No network, no real time, no shared state between tests.
5. **A bug fix starts with a test that reproduces it.**

Where tests live: `:core` in `core/src/commonTest`, `:app:shared` in `app/shared/src/commonTest`, the importer in `tools/import/test_*.py` (standard `unittest`, offline fixtures). Commands are under "Build, run and test".

## Module layout

Seven Gradle modules are wired via `settings.gradle.kts` with typesafe project accessors (`projects.core`, `projects.app.shared`, etc.):

- **`:core`** — pure-Kotlin shared logic for **all** targets including the server (iosArm64, iosSimulatorArm64, jvm, js, wasmJs, android). No Compose dependency. This is the only module the server can depend on alongside `:app:shared`.
- **`:app:shared`** — Compose Multiplatform UI shared across Android/iOS/Web. Targets iOS, JS, Wasm, and `android` (the Android library target; no JVM target — the server cannot consume it). Exposes `api(projects.core)`. iOS framework is built as a static framework named `Shared`, bundling the content of the country `-Pcountry` names.
- **`:app:content:sk`** and **`:app:content:cz`** — one country's question banks, pictures and videos each, as Compose resources. An app bundles exactly one (see [docs/countries.md](docs/countries.md)).
- **`:app:androidApp`** — Android `com.android.application` entry, with a product flavor per country. `MainActivity` just calls `App(bundledContent)` from `:app:shared`.
- **`:app:webApp`** — Compose Multiplatform web entry; produces both JS and Wasm executables that mount `App(bundledContent)` via `ComposeViewport`, for the country `-Pcountry` names.
- **`:server`** — Ktor Netty server (`com.spiraclestudios.autoskola.ApplicationKt`), depends on `:core`.
- **`app/iosApp/`** — Xcode project that links the `Shared` framework from `:app:shared` and calls `MainViewController()`.

Cross-module rule of thumb: shared **business logic** that the server also needs goes in `:core`. Shared **UI** goes in `:app:shared/commonMain`. Anything Compose-related must not leak into `:core`.

## Rules that are easy to break

Each is explained in its guide; these are the ones a change most often trips over.

- **Never hand-edit the generated question banks, pictures or videos**, and **never delete `tools/import/cache/`** — it holds about two hours of work against the ministry's server ([docs/question-banks.md](docs/question-banks.md)).
- **Never hardcode user-visible strings.** Add them to `i18n/Strings.kt` in all four languages ([docs/ui.md](docs/ui.md)).
- **Every composable gets a `@Preview` in the same change** ([docs/compose-previews.md](docs/compose-previews.md)).
- **iOS code cannot be compiled on Windows.** Say in the commit or the summary that the iOS side was not built ([docs/platform-code.md](docs/platform-code.md)).
- **Change versions only in `gradle/libs.versions.toml`**, and check the `kotlin-stdlib` a new library pulls in before integrating it ([docs/dependencies.md](docs/dependencies.md)).

## Build, run and test

The README has the canonical commands; key ones:

- Android debug APK: `./gradlew :app:androidApp:assembleSkDebug` (or `assembleCzDebug`; see [docs/countries.md](docs/countries.md))
- Web (Wasm, dev): `./gradlew :app:webApp:wasmJsBrowserDevelopmentRun` (add `-Pcountry=cz` for the Czech app)
- Web (JS, dev): `./gradlew :app:webApp:jsBrowserDevelopmentRun`
- Server: `./gradlew :server:run`
- iOS: open `app/iosApp/` in Xcode and run.
- Store screenshots: `./tools/screenshots/take-screenshots.sh` (or `.ps1`) runs the `StoreScreenshots` instrumented test on a phone, a 7-inch tablet and a 10-inch tablet emulator, one at a time, pulls the PNGs into the git-ignored `store-screenshots/` and checks the tablet ones against the store's size and 16:9 rules (see [docs/store-screenshots.md](docs/store-screenshots.md), which also says how the tablet AVDs are set up). It is the only instrumented test, and `connectedAndroidTest` skips it. A new screen in the listing gets a `capture` call there.

Tests:

- Core logic: `./gradlew :core:jvmTest`
- Shared app code (Android host): `./gradlew :app:shared:testAndroidHostTest`. Android resources are enabled in host tests (`withHostTest { isIncludeAndroidResources = true }`).
- Shared app code on other targets: `./gradlew :app:shared:iosSimulatorArm64Test`, `:app:shared:wasmJsTest` or `:app:shared:jsTest`.
- Server: `./gradlew :server:test` (uses `ktor-server-test-host` + `kotlin-test-junit`).
- Importer: `./tools/import/test.sh` (or `test.ps1`). `test_import_minv.py` covers parsing and matching with offline fixtures. `test_bank_output.py` checks the committed banks and images, so run it after every import.
- Style: `./gradlew ktlintCheck` (ktlint, IntelliJ style, rules in `.editorconfig`). `./gradlew ktlintFormat` fixes most findings.
- To run a single test, append `--tests "com.spiraclestudios.autoskola.SomeClassTest.someMethod"` to the Gradle task.

On Windows use `gradlew.bat` (e.g. `.\gradlew.bat :server:run`). Gradle configuration cache and build cache are both on; if you see odd cache behaviors, `--no-configuration-cache` is the first thing to try.
